# Pairing V3 signing-key operations

The dev Pairing Authorization signing seed is generated by
`KaevoPairingV3AuthorizationSigningSecret` in AWS Secrets Manager. It is a
43-character, base64url-compatible value that decodes to the required 32-byte
Ed25519 seed. The secret has `Retain` policies and the API Lambda receives it
only through a CloudFormation dynamic reference. Its execution role can read
only that exact secret ARN.

The seed must never be copied into Git, SAM parameters, Lambda logs, CloudWatch
events, build output, terminal history, or CloudFormation outputs. A missing or
malformed value fails authorization issuance closed with the existing
`pairing_dependency_failure` response.

## First dev provisioning

The reviewed dev deployment creates the retained
`KaevoPairingV3AuthorizationSigningSecret` with Secrets Manager-generated
entropy. Its dynamic reference and exact `GetSecretValue` permission belong
only to `KaevoCloudApiFunction`; identity Lambdas never receive this seed.

After that deployment is healthy, derive the separately distributable public
verification material with `scripts/derive-pairing-v3-public-key.py`. The tool
accepts only the secret identifier, AWS profile, region, and `kid`; it neither
accepts nor prints a seed. It outputs only a compact JSON object containing the
safe public key and `kid`, which are then pinned in the private iOS and Plugin
validation candidates. Do not enable V3 until both candidates pin that output.

## Verification keys and rotation

The issuer advertises `PAIRING_V3_AUTHORIZATION_KEY_ID`. Plugin and iOS
verification configurations are keyed by that `kid` and may contain a bounded
old/new public-key overlap. The private seed remains only in Secrets Manager.

For a dev rotation: create a new retained secret and new `kid`, derive and
publish the new public key to the private iOS and Plugin candidates, retain the
old public key for at most the authorization/recovery retention window, update
the Lambda dynamic reference and active `kid` in one reviewed change set, then
remove the expired public key from a later reviewed candidate. Do not replace
or delete the existing secret as part of normal rotation. Production key
provisioning is a separately authorized operation.

## Rollback

If the deployment must roll back, restore the preceding Lambda environment
reference and active `kid`; its retained secret remains available. Do not log
or retrieve seed material to perform rollback.
